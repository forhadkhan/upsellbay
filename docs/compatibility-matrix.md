# UpsellBay Compatibility Matrix

UpsellBay is built as an additive WooCommerce AOV offer layer. It preserves the store's existing checkout and uses WooCommerce APIs for order, product, cart, and order-item behavior.

## Current Compatibility Position

| Area | Status | Notes |
| --- | --- | --- |
| HPOS | Supported by architecture | Attribution uses WooCommerce order and order-item object methods. Final HPOS enabled and disabled QA evidence is required before release. |
| Classic checkout | Supported | `classic-checkout.spec.js` passes against a real order flow. A shipped bug in the free host plugin (wrong enqueue filename) made the classic checkout_bump checkbox silently non-functional — offer rendered, toggle did nothing; fixed 2026-07-18. |
| Block Checkout | Supported after E2E proof | Real run of `tests/e2e/block-checkout.spec.js`, 7/7 passed, 2026-07-18. A prior "7/7" claim (2026-07-17) was based on assertions that passed unconditionally regardless of whether anything rendered; removing that pattern surfaced and led to fixing four real bugs (Store API namespace mismatch, offer data on the wrong Store API schema, a JS/PHP hook-timing race, and a cart-refresh race that could wipe in-progress checkout form fields and left the offer checkbox's visual state stale after accept). Full suite: 41 passed / 0 failed / 5 skipped (documented preconditions, not costume assertions). Evidence: `tests/e2e/evidence/block-checkout-proof.json`, regenerated by `scripts/verify-block-checkout-proof.sh` — re-run it whenever Block Checkout integration code changes. |
| WooPayments | Not pursued for v1 proof | Blocked on a real OAuth account connection in this environment; Cash on Delivery was used as sufficient proof of the checkout REST/order-creation path instead (decision recorded 2026-07-18). Full gateway matrix deferred to v1.1. |
| Stripe for WooCommerce | QA required | Normal checkout compatibility only; no gateway-tokenized one-click upsell claim. |
| PayPal Payments | QA required | Normal checkout compatibility only. |
| WooCommerce Subscriptions | Limited until tested | Subscription products must not receive recurring discount leakage. |
| Multicurrency plugins | Deferred broad support | v1 attribution reports store currency only unless a specific integration is tested and documented. |
| Product bundles/composites | Not supported as offer targets | Offers may only target a simple product or a specific variation, on every placement (product page, cart, checkout, thank-you). Composite, bundle, grouped, and variable-parent products are rejected at save time. A third-party bundle/composite product's own price-recalculation logic can run after UpsellBay's on a shared cart line and silently overwrite an applied discount, so this is a correctness guard, not an arbitrary restriction. |
| Checkout replacement plugins | Warning-only | UpsellBay detects known replacement checkout plugins where possible and avoids unsafe injection. |
| CartBay | Coexistence guidance only | UpsellBay does not require CartBay and must not read or write CartBay options, sessions, metadata, routes, jobs, or recovery state. |

## Review Rule

Do not market or submit a compatibility claim unless the matching Phase 7 evidence is current in `.meta/qa/release-validation.md`.
